# 需求与边界

本页为公开整理版，不是完整验收或已实现声明。

## 产品目标

- 客户端先以H5消费现有事件/回应API，再以H5＋原生壳接入通用安卓，支持文本、按钮和文字回应；安卓产品目标未取消。原Compose工程/资料保留、暂停扩展，不迁签旧结论给Web或新壳。
- 回应绑定准确来源、代次、原会话、所见事件与交互版本、目标修订及期限；来源进展和结果追加到同一事件。
- 单人自托管也须认证，隔离用户设备与来源权限；来源文本、模型判断或记忆不能授予权限。
- 网络失败、崩溃、重复点击不应造成盲目重复输入；效果未知时保存原操作并查询原回执。
- 分别展示已读、通知各层、来源收件、执行与验证，不将 AI 自报结果当验收。
- 可替换助理，保留公共配置、偏好与历史；不自动迁移在途任务、私人上下文或授权。

## 首轮范围

个人自托管、一个既有事件服务、一个独立AI App测试会话；业务目标仍为文本卡片、按钮/文字回应、同一事件的进展与结果。用户确认H5先行，随后在安卓H5＋原生壳复用界面/业务；后端Node.js LTS / Fastify / TypeScript / SQLite及原事件/回应合同不重做，不新增后端或消息队列。前端库/壳/桥接由各自TASK落实，本页不预冻结实现。

通知采用可选自托管ntfy / UnifiedPush；扩展先保持薄接口。通知/后台/锁屏、系统权限、Keystore安全存储和生命周期必须另接原生能力及真实平台证据，浏览器前台/存储不能替代。H5不自动解决大缓存、序列化/解码、渲染和WebView开销；原Compose、桌面浏览器、原生壳和真机验证分层，不相互迁签。方向见[D01/D02/D13摘录](decisions.md)，执行与未覆盖范围仅见[唯一实施路线公开摘录](roadmap.md)；地图HTML只做文档查漏，不是产品界面。

## 后续需求（并非已实现）

本地出站连接器、Uniflo 只读观察、更多来源适配、可分享模板与工作方式、外部记忆接口、完整插件生命周期、复杂表单、附件、备份后可信对账及受控恢复。优先级和发布范围仍待明确，不因首轮收窄而视为取消。

## 不作承诺

后台通知绝对即时或必达；跨外部系统天然 exactly-once；任意 AI 工具可自动写回；DSH 原生兼容；物理设备/厂商省电全覆盖；正式公网部署、持续模型调用或生产恢复已验收。

接口实现以源码和组件说明为准。静态检查、合成自动化、隔离集成、安卓模拟器、物理设备、生产验证是不同层级。
