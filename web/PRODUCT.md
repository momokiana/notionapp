# 通知与交互：Web 客户端

## Register

product

## Users
个人自托管用户，在桌面浏览器或手机中核对来自程序/助理的一件事，再作明确回应。产品不是聊天工具，NotionApp 仅为目录名。

## Product Purpose
当前事件的查看、回应、服务保存、来源处理与结果留在同一事件。成功取决于准确目标、持久原请求与真实分层回执，不取决于页面是否看起来在线。

## Brand Personality
准确、克制、可追溯。这是从需求 R05–R09/R13/R15 提炼的本客户端实施语气，不是已经命名的产品品牌。

## Anti-references
不把工程地图当收件箱；不用聊天气泡掩盖事件/交互版本；不用营销 hero、统计卡片或“发送成功”掩盖保存与执行的区别；不复制私人助理人格。

## Design Principles
- 正文与当前问题先于装饰，动作带明确对象。
- 所见版本改变就重新确认，不替用户猜选择。
- 已读、事项决定、服务保存、来源收件、执行与核验分别表达。
- 断网和未知是可理解的状态，不能靠新 ID 或清空记录变绿。
- 手机与桌面复用业务界面，原生能力必须另有真实实现。

## Accessibility & Inclusion
标准 HTML 控件、可见标签、键盘焦点、44px主要触达、状态文字不只颜色、长文换行、200%缩放、减少动态效果。以 WCAG AA 文本对比为实施目标，实际自动/人工覆盖另见任务证据，不自称全面认证。

## Scope authority
产品/用户约束取自 ../docs/requirements.md、../README.md 和用户已批准的 H5 任务；精确实现合同见 ../docs/tasks/web-001-event-client.md。仅本 Web 客户端上下文，不是第二份共享路线或产品需求。
